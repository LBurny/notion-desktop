# Notion Desktop v0.2.8 更新说明

[English](https://github.com/LBurny/notion-desktop/releases/tag/v0.2.8) | 中文

---

**本次发布：继续修复暗黑模式窗口白边在部分电脑上仍出现的问题，并加文件日志便于跨机器定位剩余断点。**

1. **修复：DWM 调用自动回退 PowerShell 7。** 前几版用 `powershell.exe`（Windows PowerShell 5.1）通过 `Add-Type` 内联编译 C# 来调 DWM 深色属性。但部分机器上 5.1 跑 `Add-Type` 会闪退/失败，属性永远设不上去，白边一直残留——而这台机器的 PowerShell 7（`pwsh`）正常。现在应用**先试 5.1，失败（无结果）自动回退 pwsh 7**，覆盖两种环境。日志 `[dwm]` 行带来源 shell，便于确认走了哪条。

2. **DWM/主题调用写文件日志 `nd-dwm.log`**（位于 `%APPDATA%\notion-desktop\`）。每次启动、主题切换都会追加一行，记录：启动时主题、`onApplied` 是否触发、DWM 属性设置结果（`ok attr=20/19` 或 `fail r20=… r19=… cp=…`）、所用 shell（powershell/pwsh）、失败时的错误与 stdout 片段。打包版看不到控制台，文件日志是唯一排查手段。

> 排查过程：同版本(19045)机器一台生效一台不生效，逐一排除了 DWM 属性号（20→19）、系统「边框显示强调色」、主题上报时机（v0.2.7 已修）后，最终用读回属性值确认——应用把窗口属性留在了浅色(0)，根源是 in-app 调用 `powershell.exe` 5.1 在部分机器上 Add-Type 编译 C# 会失败。若装了本版白边仍在，把 `%APPDATA%\notion-desktop\nd-dwm.log` 内容发回即可定位：`nd-dwm ok` 但白线仍在说明另有来源（如视图底色层）；`fail`/`no-status` 则按 `cp=` 与 `err=` 继续修。

**测试**：新增 shell 回退链、`parseStatus`、日志上报用例，全量 **273 单测过**。
